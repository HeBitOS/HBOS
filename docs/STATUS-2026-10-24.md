## 一、这次交付

### 1. deb / zst 兼容性（`HPT/tools/pkg2hax.py`）

| 之前 | 现在 |
|---|---|
| 只按扩展名判断压缩（`name.endswith(".zst")`），Debian 12+ 常见 `data.tar.zst` 若成员名变体就解错 | **先看 magic 再看扩展名**：zstd `28 B5 2F FD`、gzip `1F 8B`、xz `FD 37 7A 58 5A`、bzip2 `BZh` |
| zstd 只走外部 `zstd` 命令，命令不在时抛 `FileNotFoundError`，看不出是哪一步 | 三级回退：`zstandard` 模块 → `pyzstd` → `zstd` 命令；全都没有时抛一条**能照做**的错误（含包名与安装建议） |
| 不支持老包的 `data.tar.bz2` / `data.tar.lzma` | 都支持 |
| 解压结果不校验，压缩流被当 tar 解析时报"找不到文件" | 解完校验 USTAR magic（偏移 257），不是 tar 就报**成员名 + 前 8 字节** |

测试：`HPT/tests/test_deb_compression.py`，内存里现造 4 种 `.deb`（gz/xz/bz2/zst）
走完整 `convert_package()`，4/4 通过；zst 用例在无 `zstd` 命令时自动 skip。
已接入 `HPT/Makefile` 的 `make test`。

### 2. zlib-tree 基准包（`tools/genhpt_repo.py`）

原来是"一个假 .so + 一条链接"的占位，安装器三条路径（建目录 / 建链接 / 写文件）
任何一条写错都测不出来。现在是一个真实的 zlib 开发包形态：

```
/opt/zlib-tree/usr/include/{zlib.h,zconf.h}
/opt/zlib-tree/usr/lib/{libz.so.1.3.1,libz.a}
/opt/zlib-tree/usr/lib/libz.so.1 -> libz.so.1.3.1
/opt/zlib-tree/usr/lib/libz.so   -> libz.so.1
/opt/zlib-tree/usr/lib/pkgconfig/zlib.pc
/opt/zlib-tree/usr/share/doc/zlib-tree/README
```

共 15 条 manifest 条目（13 目录/文件 + 2 符号链接），带 sha256 与 mode；
装完 `ls usr/lib` 应有 4 项、`cat pkgconfig/zlib.pc` 内容正确，才算多文件树是通的。
包体积 20 KB，仍远小于 RAMFS 单文件上限（128 KB）。

### 3. 设置：窗口与层级 + 更高 DPI

- 新增「窗口与层级（降维打击）」分区，三个**独立**开关：
  `可拖动化`（关掉后标题栏只聚焦不移动）、`立体层次`（拖动时的 3D 退层）、
  `降维打击`（撞击时把对方打下一层），并显示层级上限 `2^32-1` 与当前最高层。
- DPI 预设从 5 档扩到 7 档：自动 / 85 / 100 / 125 / **150 / 175 / 200%**。
- 设置页内容比窗口高（约 980px），修掉"滚轮在设置里完全无效"的缺陷：
  `app_settings_wheel()` 之前只有声明、没有任何调用点，滚轮分支现在接上了；
  点击坐标也与绘制用同一套滚动偏移（否则滚过之后整屏错位）。
  另补了拖滚动条跳转（点击轨道按比例定位）。

### 4. 手稿②：立体层级 + 降维打击

按手稿"拖动窗口时把之前的窗口渲染为 3D，撞到就把那个窗口打到下一层级，
层级上限 2^32-1"落地：

- `ui_window_t.layer`：**uint32 单调序号**，聚焦/新建时 `++layer_seq`；
  `WM_LAYER_MAX = 0xFFFFFFFF`，逼近上限时整体重标定，避免回绕后新旧层反转。
- `wm_knock_down(wm, idx, target)`：被撞窗口降到"撞击者下一层"，若该层已被占则
  继续下移，不会低于 0。因为层级号全局唯一，"下一层不会被上一级打到更下层"
  天然成立——撞它的永远是当前这一层。
- 绘制：拖动中，非活动窗口按**层级差 + 平滑后的拖动速度**做视差后退、
  压暗（`0x30 × depth`）并在左侧加一道"层厚"竖向渐变；松手归零，窗口回原位。
  只改绘制坐标，不动窗口真实几何，命中测试不受影响。
- 立体效果要求"同一帧里所有窗口共享一套视差"，所以拖动期间走整帧重绘
  （分块重绘会出现半暗半亮的接缝）。

## 二点五、④ 补强：能装"非命令行"的 GUI 软件，普通用户也能装

上一轮 ④ 的自评是"能装、报缺依赖"，但有个硬伤：装完只有 `/bin/<包名>`
一个入口，开始菜单靠**盲扫 /bin** 凑数——于是名字是包名（`calc`）、图标
全一样，连 `libc6`、`zlib-tree` 这种纯库包也冒出来（点了必然失败）。
这一轮把"安装"和"应用可见性"之间的链路按 Linux 的规矩重做：

### 1. 包元数据：.desktop 成为"这是不是 GUI 应用"的唯一依据

- `HPT/tools/desktop_entry.py`：解析/生成 `.desktop`（忽略 `Name[zh_CN]`
  这类 locale 变体，读 `NoDisplay`/`Keywords`/`Categories`）。
- `pkg2hax.py`：从 deb 的 `usr/share/applications/` 提取条目，写进
  manifest 的 `apps[]` 与 `kind`（gui / cli / lib），并把原始 `.desktop`
  打进载荷的 `.HPT/apps/<id>.desktop`。
- `tools/genhpt_repo.py`：索引从 8 列扩到 12 列
  （`…|desc|kind|显示名|图标|分类`）。HIVE 的 `.hax` 应用没有包内
  desktop 文件，就从 `.haxmeta` 的 kind 位（GUI/GUI_WIN）与描述补一份，
  装完显示「计算器」而不是 `calc`。

### 2. 注册表：只认 `.desktop`，不再盲扫 /bin

- 新增 `src/gui/desktop_entry.c`（纯字符串，无 libc/VFS 依赖，宿主可测）
  与 `src/gui/app_registry.c`（扫目录、写条目、按包名回收）。
- 两个作用域，与 FHS/XDG 对齐：
  `~/.local/share/applications`（普通用户可写）与
  `/usr/share/applications`（系统级）；同 id 用户级优先。
- `gui.c` 的开始菜单与桌面网格改为读注册表：条目名 = `Name=`、图标 =
  `Icon=`、启动走 `Exec=`；装了新应用**不重启**就能看到图标（按注册表
  代号增量重扫）。桌面网格也因此从"写死 8 个"变成"8 个 + 已装应用"。

### 3. 普通用户可用：默认用户级安装，系统级才要授权

- 安装根分两套：`~/.local/{bin,lib/hpt,share/applications,share/hpt}` 与
  `/opt + /bin + /usr/share/applications`。
- 软件商店默认「仅为我安装」——普通用户直接装、不弹权限；
  切到「所有用户」时才走管理员授权卡（5 分钟有效），过期自动降级并提示。
- CLI 侧 `hpt install` 装完也会写 `/usr/share/applications/<pkg>.desktop`
  （系统级），否则"装完菜单里没有"——这条是这轮必须补的回归。

### 4. 界面：从"安装器"改成"商店"

`src/gui/apps/app_hpt.c` 整页重写（980×620）：

- 左侧分类（全部 / 图形应用 / 命令行 / 库与运行时 / 已安装，带计数）、
  底部显示当前安装位置（`~/.local` 或 `/opt`）+「同步软件源」。
- 中间卡片流：图标 + 显示名 + `包名 v版本 · 大小` + 摘要，右侧状态徽标
  （获取 / 安装 / 已安装）。
- 右侧详情：大图标、分类/安装状态、说明、版本/大小/架构/依赖、
  "安装到 ~/.local（无需权限）"，底部「获取安装 · 打开」「卸载」与进度条。
- 布局与命中测试共用**同一个** `hpt_store_layout(draw=0/1)`，避免上一版
  "绘制与点击各算一套 y 导致整屏错位"的老问题。

### 5. 演示包：画板（`store-demo/paint.c`）

镜像里原来没有任何"可安装的图形应用"，商店装了也没东西可看。新增
`store-demo/paint.c`：一个用 `hax_win_open` + `hax_win_blit` 的 400×300
画板（6 色调色板、鼠标拖动作画）。它**不进 HAX 内置清单**，只编译到
`build/store-demo/` 并由 `genhpt_repo.py` 打进仓库——所以"装之前菜单里
没有、装完才出现"是真实的。
