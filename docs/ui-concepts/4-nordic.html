方案 04 · Nordic Calm

Nord 族 · 低饱和 长时舒适

以 Nord 色系为骨架：Polar Night 做深色底、Snow Storm 做浅色底、Frost 做唯一强调色，Aurora 只用于状态。 全部低饱和、低对比，强调色出现面积刻意压到最小 —— 目标是让 13 个应用在长时间使用下都不刺眼、不疲劳， 同时每一处文字与背景仍满足可读性下限。

/* gui/theme.h —— 唯一颜色来源；两套主题共用同一结构体 */
typedef struct {
    gui_color_t bg, surface, surface2, surface3;   /* 底 → 面板 → 次级面 → 悬浮 */
    gui_color_t line, line2;                      /* 分隔线 / 强描边 */
    gui_color_t fg, fg2, dim;                     /* 文字三层级 */
    gui_color_t accent, accent_fg, accent_hover;   /* 强调 + 其上文字 + 悬浮 */
    gui_color_t ok, warn, err, sel;                /* 状态 + 选中底 */
    uint8_t     radius, radius_small;              /* 6 / 4 */
    uint8_t     shadow_alpha;                     /* 0–255，深色 102 / 浅色 26 */
} gui_theme_t;

/* 应用侧不出现任何字面颜色：*/
gui_rect(win, x, y, w, h, T->surface);
gui_rect_border(win, x, y, w, h, T->line, T->radius_small);
gui_text(win, label, T->fg);
gui_text(win, hint,  T->dim);
gui_rect(win, btn,  T->sel);          /* 选中行 */

为什么低饱和对 HBOS 特别重要：低对比、低饱和的配色在廉价面板和低色深输出（RGB565 / 6-bit FRC、VGA 抖动）上产生的色带与抖动明显更少 —— 相邻令牌之间的色差本来就小，量化误差被藏进同一段灰蓝里， 不会像高饱和霓虹色那样在渐变和半透明上“炸”出条纹。同时因为明度差足够，即使降色深也不会丢层级。 代价是：accent 必须保持唯一、面积小，一旦滥用就没有东西能“跳出来”了。
迁移动作：把现有的 cyber_neon_* 宏整体替换为 gui_theme_t 实例 （theme_dark / theme_light），13 个应用只改引用点，不改布局；切换主题即换指针后重绘。
